🎬 Three capture modes — run all three
Do NOT run only one mode. You need isolated frames for the fine-grained Stage 2 classifier AND mixed scenes for Stage 1 detector. Each mode has a distinct training purpose.
Mode A — isolated single object
For Stage 2 fine-grained classifier (duck vs swan)
  • ✓ ONE duck OR one swan only in scene
  • ✓ Empty water surface — no distractors
  • ✓ Camera aimed directly at the object
  • ✓ Full azimuth rotation around object
  • ✓ Distance range: 1.5 – 8 m
  • ✓ Max pose variation — all rotation angles
  • ✗ No rock/log/lilypad/turtle present
~2,000 duck + 2,000 swan frames
Mode B — full pond scene
For Stage 1 detector training
  • ✓ 1–2 duck/swan placed randomly
  • ✓ 3–6 distractors scattered on surface
  • ✓ Partial occlusion between objects OK
  • ✓ Camera at random angle and distance
  • ✓ All classes present and labeled
  • ✓ Crops from this mode also feed Stage 2
  • ✓ Realistic robot navigation simulation
~5,000 mixed pond scene frames
Mode C — distractor-only negatives
For "other" class and anti-hallucination
  • ✗ NO duck or swan anywhere in scene
  • ✓ 4–8 distractor objects scattered
  • ✓ Include pure empty-water frames too
  • ✓ All objects labeled "other"
  • ✓ Camera at all angles and distances
  • ✓ Prevents model hallucinating ducks
  • ✓ Teaches what a "no-target" scene is
~2,000 distractor-only frames
Final dataset composition (total ~11,000 frames):
Mode A — duck (2000) + swan (2000) → feeds Stage 2 classifier directly
Mode B — mixed (5000) → feeds Stage 1 detector; Stage 2 also gets auto-cropped ROIs
Mode C — negatives (2000) → feeds Stage 1 "other" class; trains anti-hallucination
📷 Gosling camera setup in Replicator
The SDG camera must reproduce exactly what Gosling's camera sees on the water surface — same height, same tilt, same focal length

Fixed / match-Gosling parameters

  • Height above water: match Gosling's real camera mount (approx 0.3 – 0.5 m)
  • Tilt below horizon: 5° – 15° downward toward water surface
  • Focal length: match Gosling's real camera exactly (e.g. 24mm)
  • Resolution: match Gosling's sensor resolution exactly
  • Camera position prim path: attach to /World/Gosling/camera_mount or spawn at (0, height, 0)

Randomized per frame

  • Azimuth (yaw): 0° – 360° — simulates Gosling pointing in every direction
  • Distance to target: 1.5 – 12 m — near vs far encounters
  • Height jitter: ±0.08 m — small waves affect Gosling's body pitch
  • Tilt jitter: ±4° — water surface movement

Replicator camera code pattern

# Camera anchored at Gosling position, looking at target object
camera = rep.create.camera(
  position=(0, 0.4, 0),              # 0.4m above fluid surface
  focal_length=24.0,               # match Gosling's real lens
  clipping_range=(0.1, 50.0),
)

with rep.trigger.on_frame():
  with camera:
    rep.modify.pose(
      position=rep.distribution.uniform((-0.05, 0.3, -0.05), (0.05, 0.5, 0.05)),
      look_at="/World/Targets/current_target",
    )
🎲 All variation parameters to randomize
Every dimension you randomize is a shortcut the model cannot learn — domain randomization is what makes sim-trained models work in the real pond
● Camera ● Objects ● Environment
Duck/swan position
X,Z: uniform(−8, 8) m on fluid surface; Y = 0 (on water)
Bird appears at every distance and bearing from Gosling
Duck/swan yaw
uniform(0°, 360°)
Front, side, rear, and every angle between — essential for fine-grained features
Duck/swan pitch
uniform(−10°, 10°)
Bird bobbing on water surface; slight head-up / head-down poses
Object scale
uniform(0.88, 1.12) — scale each axis independently or uniformly
Handles variance in 3D asset size and apparent size at different distances
Distractor positions
Scatter uniformly across fluid surface; exclude a radius around duck/swan
Distractors appear near and far, in all spatial relationships to targets
Camera azimuth
0° – 360° (look_at target, orbit around it)
Simulates Gosling navigating to any heading on the pond
Camera distance
uniform(1.5 m, 12 m) from target
Model sees object at small, medium, and large apparent sizes
Camera height jitter
uniform(0.3, 0.5) m above water; ±0.08 m noise
Water wave motion slightly pitches Gosling's body
Sun/dome intensity
uniform(200, 3500) lux; color temperature 3200–7000 K
Dawn, noon, overcast, dusk — model sees bird in all lighting
Sun angle
Azimuth 0–360°; Elevation 10°–80°
Prevents model from using shadow direction as a class cue
HDR sky/dome
Swap from pool: sunny, overcast, cloudy, misty, golden-hour
Sky reflection on water changes drastically; model must ignore it
Water roughness
uniform(0.0, 0.55) — calm to moderately choppy
Water reflections / ripples change drastically around objects on the surface
Water color
Hue slight variation; albedo ±15%
Brown murky vs blue clear pond prevents colour-keying on water
Subframes
2–4 RT subframes for path-traced quality
Higher subframes = better material rendering, fewer noise artifacts
🏷 Labeling — how to ensure correctness
Labels are assigned at the USD prim level before the script runs — the simulator guarantees pixel-perfect annotations at render time, with zero human error

Step 1 — assign semantic labels to each USD prim

from isaacsim.core.utils.semantics import add_labels

# Target objects — distinct labels
add_labels(duck_prim, labels=["duck"], taxonomy="class")
add_labels(swan_prim, labels=["swan"], taxonomy="class")

# Distractor objects — all get "other"
add_labels(rock_prim,   labels=["other"], taxonomy="class")
add_labels(log_prim,    labels=["other"], taxonomy="class")
add_labels(lilypad_prim, labels=["other"], taxonomy="class")
add_labels(turtle_prim, labels=["other"], taxonomy="class")

# If you want fine-grained distractor labels too
# (useful for debugging or future expansion):
add_labels(rock_prim, labels=["rock"], taxonomy="class")

Step 2 — enable annotators in BasicWriter

writer = rep.WriterRegistry.get("BasicWriter")
writer.initialize(
  output_dir="./pond_dataset",
  rgb=True,
  # Primary label annotations
  bounding_box_2d_tight=True,    # for training
  bounding_box_2d_loose=True,    # for occlusion check
  semantic_segmentation=True,   # for visual verify
  instance_segmentation=True,   # per-instance masks
  distance_to_image_plane=True,# depth for 3D
  bounding_box_3d=True,        # 3D bbox optional
)

Step 3 — verify labels before running bulk generation

Visual check — semantic segmentation image Inspect the semantic_segmentation PNG. Duck must be one solid color, swan a different solid color, each distractor a third color. If any object is black or background-colored, its semantic label was not applied correctly to the right prim path.
Bounding box overlay check Render the bounding_box_2d_tight boxes on top of the RGB image. Boxes must be tight around the visible silhouette. If a box covers the entire image, the semantic was applied to the world root instead of the object prim. If boxes are missing, the prim path in add_labels() does not match the actual prim in the stage.
JSON content check Inspect the bounding_box_2d_tight JSON. Confirm: "label" values are exactly "duck", "swan", "other" (no capitals, no spaces, no typos). Check "occlusion" is populated (0.0 = fully visible). For any frame where occlusion > 0.6 for a target object, skip that frame during training data export.
Prim path strategy to avoid mislabeling Give each object a clear prim path hierarchy: /World/Targets/Duck_01, /World/Targets/Swan_01, /World/Distractors/Rock_01. Apply add_labels() to the root prim of each asset (the Xform node, not a mesh child). Use check_missing_labels() to detect any unlabeled objects before capturing.
